## Comparison history

### Iteration 1

- P2 — The event pass was too flat relative to the source's beveled red/blue slab, and its width obscured too much of the Taipei skyline.
- P2 — The first section transition lacked the source and deck's technical-grid texture.
- Capture note — The first capture was taken before the entry animation had settled. It was discarded as invalid evidence and recaptured after 1.35 seconds.

### Fixes

- Reduced the pass maximum width from 670 px to 620 px to restore skyline and Taipei 101 visibility.
- Added an optimized generated `event-pass-frame.webp` overlay while keeping all event facts and actions code-native.
- Added `technical-grid.webp` to the section-transition surfaces.
- Repeated desktop and mobile captures after all entry motion completed.

### Iteration 2 — User screenshot refinement

- P2 — The 1536 × 1024, 21 KB technical-grid asset was being enlarged across a 1512 CSS px Retina viewport, so its subtle lines and dark texture appeared soft.
- P1 — The event pass used only a planar `rotateZ(1.2deg)` rotation. Changing it to `rotateZ(-2deg)` altered the top edge but still did not recreate the reference's four-corner perspective.

### Fixes

- Re-rendered the grid with cleaner line detail, then produced a 3072 × 2048 Retina-ready WebP at 171 KB with high-quality resampling and sharpening.
- Updated all section backgrounds to `technical-grid-2x.webp` and removed the unused 1536 × 1024 asset.
- Re-captured the hero at 1440 × 1024 and the background at the user's normalized 1512 × 982 viewport.

### Iteration 3 — Four-corner perspective correction

- P1 — The `-2deg` planar revision was rejected by the user because it only made the left side look crooked. The reference instead shows a tall trapezoidal slab: both lower corners shift left, the top edge stays nearly level, and the lower edge opens down toward the right.

### Fixes

- Replaced the planar base rotation with a composed desktop transform: `rotateX(-7deg) rotateY(-8deg) rotateZ(2.5deg) skewX(-5deg)` under a 1400 px perspective.
- Kept pointer movement as small deltas around that base transform instead of replacing the designed perspective.
- Added a responsive right margin so the projected upper-right corner remains inside the arena frame at both 1440 px and the user's 1512 px viewport.
- Kept the mobile card horizontal below the 1200 px breakpoint.
- Compared the exact user reference and final implementation in a single focused event-pass image.

### Iteration 4 — Natural plane and dedicated mobile reflow

- P1 — The affine `skewX(-5deg)` was layered on top of the 3D rotations. Although the card content technically shared the same transform, the extra shear stretched the letterforms and made the card read as a distorted flat image instead of one physical plane.
- P1 — The mobile hero retained the desktop type scale and side-label metadata grid, causing the headline to break after a single final character and squeezing venue text beside a fixed label column.
- P2 — The fixed mobile action bar obscured the first viewport and competed with the event-pass actions before the visitor had finished reading the hero.

### Fixes

- Removed the affine skew and the duplicate inline perspective. The pass now uses one parent perspective with only `rotateX(-8deg) rotateY(-10deg) rotateZ(-1.8deg)`, so the frame, typography, icons, rules, and controls stay on the same natural plane.
- Preserved the intended upper-right lift and leftward lower-corner projection using the 3D axes alone.
- Added an explicit two-line headline composition, reduced mobile display scale, and tightened hero spacing without shrinking tap targets.
- Reflowed mobile pass metadata into full-width stacked rows with horizontal labels, leaving date, time, and venue values enough uninterrupted width.
- Kept the quick-action bar out of the opening viewport and reveal it only after the hero leaves the viewport.

### Iteration 5 — Reference-corner match

- P1 — A natural three-axis rotation still did not reproduce the reference's four measured corners closely enough.
- Replaced the approximate rotation with one projective matrix so the frame, surface, typography, icons, dividers, and actions share the same reference-angle plane.
- Removed pointer-driven tilt deltas because they moved the card away from the selected static visual truth.

### Iteration 6 — User-viewport scale correction

- P1 — Applying the reference image's absolute card dimensions to the browser layout produced a 743 × 809 px projected card, which was too large and approached the right and bottom viewport edges.
- Restored the authored card to 620 × 620 px and recomputed the same reference direction for that size.
- Final projected bounds at the user's 1970 × 1135 CSS viewport are 628 × 647 px, from x 1102–1730 and y 216–863, with no horizontal overflow.
- Reduced the enlarged metadata, icons, and actions back to the implementation's intended visual scale while preserving the stacked reference-button arrangement.

### Iteration 7 — Schedule-background clarity correction

- P1 — The previous `technical-grid-2x.webp` had adequate nominal dimensions but encoded a fine one-pixel grid into only 171 KB. `background-size: cover` then resampled those lines to fractional pixels across the 1970 × 1015 px schedule section, which made the grid look soft and compressed.
- Rebuilt the technical surface with stronger line definition and clean red/blue HUD details, then prepared a 3840 × 2560 production WebP at 342 KB.
- Replaced the global technical-grid treatment with quieter, section-specific arena imagery so the page stays detailed without looking busy.
- Made the schedule crop deterministic: width-driven on desktop and height-driven on mobile, avoiding arbitrary cover scaling while preserving full section coverage.
- Rechecked the schedule at 1970 × 1135 and 390 × 844 with no horizontal overflow or broken images.

### Iteration 8 — Motion-effects pass

- Added a split red/blue HUD scan to the hero and schedule without changing the sharp raster background or placing effects above interactive content.
- Added a reusable glare-sweep layer to the event pass and experience cards. The effect is pointer-transparent, hover/focus-triggered on desktop, and removed on touch-only layouts.
- Added one-shot viewport reveals for section headings and major content frames, plus a subtle repeating energy-rail pulse.
- Kept every motion layer dependency-free and isolated in `MotionDirector`, `HudScan`, `GlareSweep`, and `motion.css`.
- All ambient and reveal motion is disabled for `prefers-reduced-motion`.
- Rechecked desktop and 390 × 844 mobile layouts; no horizontal overflow, broken images, or obscured interactions were found.

### Iteration 9 — Event-pass frame, icon spacing, and skyline composition

- P1 — The event-pass frame source was an opaque black-background WebP. `mix-blend-mode: screen` hid the black only in simple stacking contexts; after projective transformation it produced a visible black polygon outside the neon frame.

### Iteration 10 — React Bits SpotlightCard interaction
